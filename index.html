paconicasiog/Cobranza-Fisicacode available on request

Problem

Formal collection notices to overdue repair shops were assembled by hand, one client at a time, and follow-up lived in scattered emails.

What I built

A pipeline that joins overdue balances in Redshift with invoice detail in Postgres, generates each notice as a PDF and files it in a per-client Google Drive folder.

  1. inputClient listshop IDs to review
  2. RedshiftCurrent debtinvoices and overdue amount
  3. PostgresInvoice detaillegal name, address, contact
  4. outputPDF + Drive foldertracking log with a link per client

Decision and process it improved

The team stopped assembling documents and started deciding who to escalate. It was one piece of the collections redesign that took late payments from 10% to 2%.

Problem

Every shop had a fixed markup by tier, even though some cancelled often, ordered over WhatsApp, paid late or cost more in logistics.

What I built

A weekly and all-time income statement per client, plus a rules engine that adjusts each markup to actual behavior.

CM3− financing cost of installments and extensions
CM4− coupons and discounts

Decision it enables

paconicasiog/data-lake-silver-data-processingpublic repo

Problem

Every new data lake table required new code, and business logic ended up buried in scripts that were hard to audit.

What I built

A serverless function that receives a Pub/Sub message, reads that table's SQL from Cloud Storage, runs it on BigQuery and writes date-partitioned Parquet.

  1. eventPub/Sub messagedataset, layer and partitions
  2. logicSQL from GCSrules live outside the code
  3. computeBigQuerytypes mapped to Arrow
  4. targetPartitioned Parquetsafe to rerun, no duplicates

Process it improved

Adding an analytics table means writing a SQL file, not deploying code. Analysts own their logic, and metrics have a single source of truth.
